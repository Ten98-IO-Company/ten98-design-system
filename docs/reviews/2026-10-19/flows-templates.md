# Flow and fixed-template critique — 19 October 2026

Baseline critique of version 0.3.4. Current remediation status is tracked in [the review overview](README.md). Raw screenshots and scripts named `.qa/…` are local, ignored artifacts; selected durable before/after evidence is linked from the overview.

All 28 reference flows and all five fixed templates were reviewed. The strongest existing pattern is truthful, scoped state: accepted versus delivered, measured zero versus unavailable, draft versus applied, and uncertain outcomes with retained receipts. Keep those contracts and Campaign’s existing brand, English labels and LTR presentation. Premium polish should come from predictable controls, readable density and quieter structure.

## Evidence and interpretation

- **Visual inspection:** 33/33 initial desktop previews captured at a 1440 × 1000 viewport and viewed in six contact sheets. Native-size C8 and D6 screenshots were additionally inspected. Four 320px dark previews were captured; C1 and D9 were inspected at native size before this report, with C6/D7 inspected during final verification.
- **Interaction checks:** all 37 existing desktop Chromium tests in campaign.spec.ts, discover-analytics.spec.ts and discover-research.spec.ts passed in 24.6 seconds. They exercise all 25 Campaign/Discover flows, including draft retention, scoped review, unknown outcomes, permission gating and important recovery paths. A focused invalid-path check in D3 disabled Run and displayed its linked validation text. Three generic flow recipes were visually reviewed against their source and documented state contracts; their separate browser harness was not rerun here.
- **Reproduced defects:** Detail/Settings section navigation leaves Templates for Components; C8 audience values wrap excessively inside the desktop preview. Neither is detected by the 37 flow checks. No page errors occurred during the 33 default captures. Four selected narrow pages had no page-level horizontal overflow; that does not imply every internal control is optimal.
- **Limits:** these are local synthetic specimens. No provider, billing, send, scheduling, deployment or production data was exercised. This is not a screen-reader, contrast-ratio, live-service or exhaustive mobile/200%-text audit. The complete existing test suite was not rerun by this worker. Most remaining findings are explicitly design judgments, not functional failures.

The baseline template chooser used five large cards before the preview. The coordinator is compacting that catalogue-only chooser separately; the screenshots in this report retain the original baseline. The fixed template API does not need to change for that improvement.

## Highest-value shared changes

1. **P2 — Repair demo navigation at its owner.** The in-page links generated by TemplateDemo collide with the catalogue hash router. Scope scroll/focus handling to the demo or use route-aware links; do not alter the DetailTemplate/SettingsTemplate slot contract. Verification reproduces the wrong Components heading both after the link and after reload.
2. **P2 — Make nested summaries respond to their container.** The desktop audience preview is narrow even on a wide viewport. Its four cards measure about 68.7px each and split Unavailable into three lines. Use two columns or a definition list at that container width. Preserve all counts and essential exclusion/permission evidence.
3. **P2 — Give report results adequate width.** D3, D4 and especially D6 use the editor preview as the complete report. Keep the compact editor context but put wide evidence tables/breakdowns below it or use an existing report/detail structure. Horizontal scrolling remains a valid fallback, not the default desktop presentation of a one-row report.
4. **P3 — Apply one visible hierarchy to task controls and demo controls.** Local outcome selectors and simulation buttons should be a labelled fixture area. Keep real configuration and current allowed actions in their established template slots. Essential unknown, partial, stale, cost, authorization and reconciliation information stays visible outside any optional disclosure.
5. **P3 — Use existing form rhythm and empty-state patterns.** Pair related date controls; keep short selects at a sensible width; use h2-led groups and the existing EmptyState instead of isolated sentences. Consolidate Save/Review/Send action placement for genuine editors without moving exact-scope review or bypassing any guarded transition.

## Reference patterns checked

These primary sources were reopened on 19 October 2026. They support comparison principles; the recommendations above are ten98 design judgments, not a claim that a competitor’s business rules should be imported.

- **R1 — [Linear, A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh):** predictable action locations, task emphasis and softer supporting structure. This does not require changing Campaign branding or making every screen sparse.
- **R2 — [Linear display options](https://linear.app/docs/display-options):** a consistent place for supported view controls. Only offer controls the consuming app actually supports.
- **R3 — [Stripe Apps components](https://docs.stripe.com/stripe-apps/components):** reference vocabulary for composing focused tasks and related context; used here to compare overview, detail and editor roles.
- **R4 — [Vercel Geist Table](https://vercel.com/geist/table):** table presentation reference; retain ten98’s native units, supplied values, captions and contained scrolling.
- **R5 — [Vercel Geist Empty State](https://vercel.com/geist/empty-state):** empty-state reference; recommended only where a clear explanation and current next action improve the task.
