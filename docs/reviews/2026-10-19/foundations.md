# Foundations critique — 19 October 2026

Baseline critique of version 0.3.4. Current remediation status is tracked in [the review overview](README.md). Raw screenshots and scripts named `.qa/…` are local, ignored artifacts; selected durable before/after evidence is linked from the overview.

## Scope and evidence

Read-only implementation and browser review of all **45** catalogue entries originating in primitives.tsx (20), patterns.tsx (18), and adapters.tsx (7). Each first-state specimen was captured and visually reviewed in light/comfortable and dark/compact at 1440px. Narrow dark/compact captures cover DataTable, PermissionMatrix, DateRangeField, Stepper, AppShell, AppField, and Card at 390px. Other supported states were read in source; this is not exhaustive interactive, contrast, or assistive-technology certification.

Evidence is in .qa/critique-foundations (local `.qa/critique-foundations/`): 90 named component/theme images, six contact sheets, seven narrow images, observations.json, and a separate interaction script. The interaction script stopped before persisting its results. Contact sheets retain unmodified rendered specimens; they resize them only for review. Open individual PNGs for readable detail. First-state captures show modal launchers and idle toast controls; dedicated modal screenshots show opened Dialog and typed ConfirmDialog.

Use **P1** for a visible usability defect that should block release, **P2** for a consistency/behavior gap worth fixing next, **P3** for optional polish, and **Keep** for a sound current treatment. **Defect** means evidenced implementation/rendering trouble; **Improvement** means a design judgment, not a standards violation. No automated full WCAG claim is made.

Campaign's logo, compatibility icon paths, and login presentation should remain. Keep English LTR and hidden sidebar scrollbars. Premium here means clearer hierarchy, dependable positioning, readable states, and intentional density.

## Shared roots to fix first

1. **P1 defect: PermissionMatrix dark cells inherit a pale legacy surface.** Screenshot permission-matrix-dark.png and permission-matrix-narrow.png show white column headers and row-label cells with pale text. src/lib/app.css:108 globally styles th with background:#fcfbfe. In src/lib/workspace.css, .t98-permission-table thead receives a theme background, but its individual th cells keep the global background. Give .t98-permission-table thead th and .t98-permission-table tbody th explicit tokenized backgrounds/text. Scope legacy table rules when compatible with existing consumers. Do not redesign every table individually.
2. **P1 defect: AppBadge status surfaces do not change with theme.** src/lib/app.css:111,113–118,332–333 use pale hex backgrounds with theme-dependent muted text. Dark screenshot app-badge-dark.png exposes the result. Map each existing status group to existing success/warning/danger/neutral surface and foreground tokens while preserving labels, dot, and status names.
3. **P2 defect in the catalogue: intrinsic components are presented as stretched bars.** src/showcase.css:91 .reference-preview-content is a grid with default item stretching. Button and Badge first-state screenshots render edge to edge, while composition elsewhere uses intrinsic actions/chips. Adjust preview alignment for intrinsic specimens; keep form fields, cards, tables and shells full width. An entry-level alignment flag or targeted existing wrapper rule is smaller and clearer than changing Button or Badge.
4. **P2 consistency debt: legacy control and empty-state chrome bypass tokens.** app.css .field input/select/textarea uses #dfd6eb borders; .empty-icon uses #f1ecfa; disabled styling targets input alone. Tokenize those existing rules and extend disabled styling to textarea/select. Preserve Campaign assets/login geometry.
5. **Optional typography pass:** ActivityFeed details/time, Badge, AppBadge and AppStat captions use 9–11px values, with AppBadge shrinking to 9px in the viewport rule at app.css:287. Increase the most decision-relevant text first. This is a readability judgment; small type alone is not a WCAG failure.

## Reference basis

- **L — [Linear, Behind the latest design refresh](https://linear.app/now/behind-the-latest-design-refresh)**, opened 19 October 2026. Applicable as a precedent for calmer visual hierarchy and predictable context/view control placement. Applying that direction to this library is design judgment, not a claim that Linear prescribes these exact tokens.
- **T — [Vercel Geist Table](https://vercel.com/geist/table)**, opened 19 October 2026. Supports semantic tables, sortable header buttons, tabular numerals, explicit missing values and readable pagination. Its advice to place underlying-list empty states outside the table is a reference-specific option to evaluate here.
- **E — [Vercel Geist Empty State](https://vercel.com/geist/empty-state)**, opened 19 October 2026. Distinguishes first-use, filtering, denied access and failure; recommends contextual action and real buttons/links. No change to ten98 sentence case is implied.
- **S — [Stripe App UI components](https://docs.stripe.com/stripe-apps/components)**, opened 19 October 2026. A comparative catalogue for using shared controls and composable patterns. Row recommendations marked S remain this audit's judgment; the source does not endorse this implementation.

## Verification and limits

The two-theme comparison deliberately combines light with comfortable and dark with compact. It does not isolate all four theme/density combinations. observations.json records state-name coverage, frame presence and horizontal page-overflow probes; source review covers the remaining documented states. Seven narrow first-state captures were reviewed, with no claim that every entry was exercised at every viewport.

interact.mjs reached Dialog, typed ConfirmDialog, Tabs and Tooltip, then stopped on an ambiguous toast launcher. No interactions.json was written; Toast and computed-color checks were not reached. The opened modal and focused tooltip screenshots remain visual evidence, with no claim of an exhaustive keyboard pass. This critique intentionally does not turn a documented adapter limitation into an invented behavior-test result.

Skill checks: design-design-critique framework applied; factchk reference claims checked against the linked primary pages; ssotize audit identifies tokens.css/app-tokens.css as canonical values and the exact app.css overrides to reconcile, with no source mutation; re0 pass keeps one final finding per component. A separate cold reader should inspect this report before handoff; nested workers were excluded by task scope. No benchmark/experiment or portability claim was introduced, so mandela/detool are inapplicable.
