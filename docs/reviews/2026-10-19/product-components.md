# Product component critique — 19 October 2026

Baseline critique of version 0.3.4. Current remediation status is tracked in [the review overview](README.md). Raw screenshots and scripts named `.qa/…` are local, ignored artifacts; selected durable before/after evidence is linked from the overview.

The product surfaces already preserve the distinctions that matter: zero versus unavailable, installation versus received events, quoted versus settled cost, public versus private messages, and confirmed versus unknown outcomes. The strongest improvement is to make that evidence easier to scan. Correct the two stylesheet leaks and the narrow-screen focus example before spending time on visual polish.

This is a critique, not an implementation change. Campaign identity, existing purple accent, English copy and LTR reading order remain the baseline. Suggestions below reuse the existing slots, native controls and tokens; they do not propose a new analytics engine, player, scheduler, provider adapter or approval policy.

## Reference direction

References were opened on 19 October 2026. The proposed applications are this reviewer's design judgments, not claims that a competitor's treatment guarantees better results.

- **[L] [Linear's design refresh](https://linear.app/now/behind-the-latest-design-refresh):** predictable placement of actions, quieter supporting chrome and stronger task emphasis. Borrow the hierarchy; retain Campaign styling.
- **[V] [Vercel Geist tables](https://vercel.com/geist/table):** semantic table structure and clear comparison layouts. Use as a comparison reference while retaining all supplied uncertainty, timestamps and source context.
- **[S] [Stripe Apps components](https://docs.stripe.com/stripe-apps/components):** consistent component composition and focused context/detail surfaces. Adapt the layout idea through the existing component slots.

Severity: **P1 = material accessibility/usability defect; P2 = meaningful consistency issue; P3 = optional polish; Keep = no change required.** No critical defect was established in this scope. Each row separates a directly observed defect from a design preference.

## Shared fixes to prioritize

1. **P1 — stop the global table theme leak.** `src/lib/app.css:108` sets unscoped `th` backgrounds to `#fcfbfe`. ReviewSummary, RetentionTable and RankComparison then show light column and row headers inside dark surfaces. In ReviewSummary, computed text `rgb(173,185,202)` against background `rgb(252,251,254)` yields approximately **1.93:1** contrast. The shared root cause is the global rule; scope legacy app table styles to their owning table classes, and give the product tables explicit semantic header foreground/background tokens. Check both header axes in all three tables. Close-up (local `.qa/critique-product/review-summary-dark-detail.png`), the baseline screenshot and the 0.3.4 stylesheet rule (the latest local computed-style file already contains coordinator fixes). This was verified in the catalogue with both stylesheet families loaded; the same rule applies wherever those styles coexist. Reference [V].
2. **P2 — demonstrate focus movement when narrow list/detail panes change.** In the DetailWorkspace example, Back correctly restores the list button after its animation-frame callback. Reopening loses focus to `BODY` after the list pane is hidden, confirmed after 180ms. Preserve the controlled draft, focus the selected detail heading when opening, and restore focus to the selected list item when returning. The application owns that behavior; fix the catalogue controller and document the integration obligation without adding router ownership to the shared presentation component. Reference [S].
3. **P2 — prevent prose styles from changing live specimens.** `src/showcase.css` selector `.reference-section p` overrides `.t98-comparison-value` in `src/lib/products.css:15`: the intended `1.75rem` metric computes to **13px**. Scope catalogue prose rules to prose children or a dedicated prose wrapper so the preview reflects the shipped component. Verify count, range, reason and metric styles independently. Reference [L].
4. **P3 — use fewer nested borders and a consistent information order.** Existing product CSS repeats bordered card-within-card treatments for operation rows, destinations, media, agenda items, funnel steps and journey steps. Where items belong to one list, prefer one enclosing boundary with subtle row separators. Keep a stronger boundary for a selected item and keep risk/uncertainty reasons visible. Use title → scope → primary value/content → status/reason → provenance → action as a consistent reading order, with exceptions where a consequential warning must precede the content. Reference [L].
