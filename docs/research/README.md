Review scores and category rank are signals for selecting references; they do not prove a flow is best. Adoption counts and detected installations are not automatically market share. Compare products by the specific task, identify denominators and source dates, and distinguish direct visual inspection from documented behavior. Preserve uncertainty where public evidence is incomplete.

Campaign's current logo, icons and login remain the visual baseline. Competitors guide task structure and behavior; they do not replace ten98 branding. Shared UI is built here with tokens and typed components. Product engines, data, permissions, reconciliation and releases belong to each app session and the human owner. ## Implementation status

All six report sets are complete for the original scope, with 18 evidence/flow/recommendation documents. Their source limitations and unaccepted feature suggestions remain recorded in each report. Shared Campaign C1–C8 and Discover D1–D17 presentation components and reference flows are implemented alongside the three cross-product recipes. See the [release validation](../VALIDATION.md) for library checks and separately tracked consumer acceptance. Reference examples do not approve new product capabilities. Specialized editors, canvases and domain features require their actual use case and data contract.

The historical Researcher [reference and flow proposal](researcher/README.md) now informs Connect's research workspace, using primary product documentation and explicitly limited user-review signals. It does not establish a popularity ranking, market-share ordering, screenshot comparison or approved feature set. Concrete tasks, categories, data contracts and any paid-provider policy remain undecided; the original reports are not implementation acceptance for Connect's research workspace.

## Accepted shared work in this wave

The coordinator selected three cross-suite compositions already covered by existing UX rules: connection verification, data investigation and scoped change review/reconciliation. They use existing library exports, include explicit demo outcomes and complete TSX, and are local catalogue recipes. App teams can review them before requesting a stable shared API. No workflow runtime, rich-text engine, telephony client, hypervisor or domain-specific backend was added.

All larger specialized editors and new feature suggestions remain in the reports' decision registers. The next coding worker needs a concrete approved task and consumer contract; it does not automatically start another parity or research wave.
